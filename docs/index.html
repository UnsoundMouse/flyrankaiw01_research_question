CTR / Engagement Opportunity Scoring · FlyRank ML Internship Capstone

Why do some page-one results get fewer clicks than others?

We studied 30,000 pages across 32 clients to find pages that already rank well but under-capture the clicks their position normally earns. Using a position-tier-adjusted CTR gap as a proxy target and a client-grouped validation split, a Logistic Regression model ranked genuine opportunity roughly 1.7× more precisely than a position-only baseline (precision@20: 0.85 vs. 0.50, base rate 0.44) — while a more complex Random Forest model did not beat that same baseline. The result is a reviewed, human-gated action queue, not an automated editing system.

01 — INTRODUCTION

The decision this supports

A content editor has limited time and a large portfolio. This study asks a narrow, concrete question on their behalf: of all the pages already ranking somewhere reasonable, which ones are quietly leaving clicks on the table — and which of those are worth a title or meta-description rewrite first?

A page sitting at position 4 with a CTR far below what other position-4 pages typically achieve is a different problem than a page with no search demand at all. The first is a metadata problem an editor can act on directly; the second usually isn't. This study builds, validates, and honestly limits a system for telling the two apart.

Cost of a wrong call: a false positive costs an editor's hour on a page that was already fine. A false negative leaves real, already-earned traffic unclaimed on a page that has the hard part — ranking, demand — already solved.

02 — DATA

Data

This study uses the FlyRank ML Internship starter release: a 90-day, single-snapshot slice of 30,000 pages across 32 pseudonymous clients (content_refresh_anonymized.csv). A larger warehouse release (79M rows, 104 clients, 17 months, access-gated) exists and was explored for data-contract practice, but every model and figure in this paper uses the starter slice, for direct comparability across every stage of the build.

Deliberately excluded

  • Client and content IDs — pseudonymous grouping keys only, never model features.
  • Trend-derived columns (30-day trend percentage and direction) — computed downstream of the same signal this study's label is built from; using them as features would let a model read the answer.
  • Rows with avg_position == 0 — this value means "no position data," not rank zero, and silently files under the best tier label if not filtered out first.
No client names, domains, URLs, or private search query text appear anywhere in this study, its notebooks, or its outputs.
03 — METHODOLOGY

Methodology

Target

underperforms = 1 if a page's CTR sits below its own position tier's median CTR, computed on pages with real, visible traffic (≥500 impressions/90 days). This is a proxy, not an observed future outcome — the data is a single snapshot, so there is no genuine before/after window to validate against. Every claim in this paper respects that limit.

Population

impressions_90d ≥ 500 and avg_position ≤ 20 — enough traffic to trust a CTR comparison, and close enough to page one that a snippet edit is realistic. This pool holds 12,023 pages.

Features

Position, word count, content age, days since last update, engagement rate, scroll rate, AI-traffic share, content type, search intent, and freshness tier — never CTR, clicks, or anything the label is computed from.

Baseline

Ranking by position alone (best position first) — the one signal the original rule-based approach can offer without seeing CTR directly, which is what makes it a fair thing for a model to be measured against.

Validation design

Client-grouped split (75/25) — no client's pages appear in both train and test. A same-task comparison against a plain random split showed only a small gap here (precision@20: 0.86 random vs. 0.85 grouped) — page-level features vary enough within one client's own portfolio that client memorization wasn't the dominant risk for this particular task. That finding is specific to this task; it isn't assumed to generalize automatically.

Leakage checks

A first pass included a session-count feature and produced a suspiciously high score. Permutation importance flagged it as dominant; its correlation with the click count used to build the label was 0.83 — a near-duplicate signal, not an independent one. It was removed. Every result below is the honest, post-removal number.

Logistic Regression clearly wins — roughly 1.7× the baseline at K=20. Random Forest does not — it falls slightly below the position-only baseline at K=20, a direct example of not rewarding model complexity on its own.

What the model leans on

Permutation importance on the honest feature set: engagement_rate leads clearly (≈0.15), well ahead of content_age_days (≈0.03) and every other feature. Its correlation with CTR (0.08) and click count (0.02) is low — unlike the removed session-count feature's 0.83 — so this looks like a genuinely separate signal, not a disguised copy of the label.

05 — LIMITATIONS

Limitations & honest framing

  • Not causal. Cross-sectional, single-window data, no experiment. This study never claims a rewrite will raise CTR — only that certain pages look worth reviewing first.
  • Proxy label, not an observed outcome. The label is defined from the same window as every feature; this ranks current relative standing, not future trajectory.
  • An intent bias, found and disclosed, not hidden. Commercial and transactional pages are compared against a tier median dominated by informational pages, and get over-flagged as a result. They're routed to human review rather than direct action specifically because of this.
  • A small, single-month slice. 30,000 rows, 32 clients, one snapshot — not yet confirmed against the full 79-million-row, 17-month warehouse.
  • External consistency, not proof. FlyRank's own March 2026 portfolio report (341,701 pages, 57 brands) independently found the same directional pattern — weighted CTR falling from 0.423% (top 3) to 0.050% (deep) — using a different, portfolio- weighted calculation. The direction matches; the absolute numbers aren't expected to, and shouldn't be read as validating each other's magnitude.
All claims in this paper follow a fixed ladder: observed (a fact about this snapshot) → directional (a pattern, not a guarantee) → decision-support (input to a human decision, never the decision itself). Nothing here reaches the next rung — a causal claim — because no experiment was run.
06 — RANKED RECOMMENDATIONS

The action playbook

Every action below requires human review before publishing. Nothing in this system is approved for direct automated edits.

1
rewrite_title_meta
High model score, non-commercial intent

Direct title/meta review — the model's strongest, least-caveated signal.

2
review_before_rewrite
High score, commercial/transactional intent

Human review first — this segment carries the known intent bias from the limitations above.

3
schedule_refresh_review
Content age 271–365 days

Proactive refresh review, ahead of the CTR signal showing up — the decay-cliff window FlyRank's own portfolio report also identifies.

4
monitor_only
Borderline score

Watch, no action yet — revisit on the next scoring pass.

5
no_action
Low score

Not flagged this round — means "not flagged," not "confirmed healthy."

What should never be automated

  • No auto-published title/meta edits, ever.
  • Nothing below the 500-impression eligibility floor — too little signal to trust.
  • model_score is never a probability that an edit will work.
  • Never applied outside this lane (CTR/engagement) — it says nothing about technical SEO, backlinks, or content accuracy.
